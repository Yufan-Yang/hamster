# 媒体管家第一阶段实施计划

目标：为已登记的媒体建立可恢复的“观察 → 计划 → 派发 → 复查”闭环。

## 范围

- 按账号盘点现有下载记录、媒体文件、已有字幕、转写、总结与章节。
- 文件缺失、存储不可用、共享源和失败下载分别记录，保留源文件和人工编辑。
- 从核实的缺项生成结构化动作；补全已有字幕、转写、总结与章节复用任务板。
- 可选 AI 只排列已批准动作的优先级；输出校验、预算限制和规则回退由代码执行。
- 用户可查看当前可见媒体的状态、触发盘点/补全、选择处理档位并启停自动补全。
- 工作进程定期分批巡检，优先复查已完成的补全任务；不要求用户保持网页打开。

第一阶段不执行批量移动、删除、替换文件或重新下载；不扫描未登记目录，不推断文件归属。
后续按资产档案扩展归档纠错、下载策略与批次管理。

## 数据与执行

- 新增资产观察表和动作流水表，账号策略存入现有 kv。
- 观察保存输入版本、产物计数、问题和计划；不保存字幕全文或模型输入输出。
- 动作派发与流水在同一数据库事务中写入；沿用唯一任务、租约和重试机制。
- 每轮有扫描、派发上限；相同输入产生无效结果时退避，达到上限后保留问题待处理。
- 只处理可信媒体根目录内的普通文件；缺文件时不重排分 P 索引。
- AI 排程不能引入新动作、文件路径或 shell 命令，按账号限频限量。
- 管理接口按当前账号及实时隐私范围过滤，后台完整巡检不会泄露隐藏媒体计数。
- 已存在且无来源版本的总结保留；新生成总结保存输入版本，以便识别过期产物。

## 验收

1. 盘点不启动媒体处理；补全仅派发计划内的合法动作。
2. 重复扫描与并发派发不会重复排任务，重启后能从流水恢复。
3. 任务成功但产物缺失不会误标完成，不会无休止重跑。
4. 存储离线、文件缺失、越界路径、分 P 缺文件、共享媒体均不会触发错误写入。
5. 现成字幕优先使用；没有字幕时按档位决定是否转写；音乐不做语音总结。
6. 人工总结不被自动覆盖；新总结输入改变后可识别过期。
7. 账号、管理员、隐私切换及慢请求返回均不泄露其他范围的数据。
8. AI 返回非法/重复动作、超时或预算耗尽时回到规则顺序。

验证使用临时数据库、合成媒体和模拟任务，不接触生产数据。

自动补全与 AI 排程默认关闭，用户保存策略后生效。部署脚本已纳入新增后端与页面回归。

- 新增 31 项隔离后端回归；连同任务生命周期、权限、总结、部署和自修复等相关回归，共 166 项 unittest 通过，分类标签脚本通过。
- 8 组相关前端回归、页面脚本语法、Python 静态检查通过。
- 实际 Chrome 在 390px 与 1280px 下验证显示、无横向溢出、保存策略与只读盘点操作；使用临时媒体与模拟接口。
- 多文件条目沿用现有主文件总结；不将文件可读取视为解码完整性证明，也不声称已经验证转写覆盖率。
- 本次仅实现和验证仓库代码，未连接生产媒体或部署服务。

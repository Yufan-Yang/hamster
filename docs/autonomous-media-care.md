# 自主媒体处理与系统修复

媒体管家现在处理两类闭环：媒体的文件/下载/内容流程，以及拾光前后端的运行问题。

## 媒体流程

默认后台检查文件归档、附件、失败下载和长时间无进展的任务；新增或更新的媒体进入下一轮检查。首页显示实际待处理事项和最近处理回执。检查本身不调用模型，也不移动文件。

开启账号的自主处理后，提案、审查、执行分开运行：

| 类型 | 默认方案 |
| --- | --- |
| 教程、讲座、纪录片、新闻 | 先用字幕，缺少字幕才转写，再补总结、章节并验收 |
| 电影、剧集 | 优先归档和已有字幕；深度档位才额外分析整集 |
| 音乐、音乐视频 | 保留文件与现成字幕，跳过额外语音分析 |
| 普通视频 | 依据内容分类与处理档位选择步骤 |

内容审查器独立核对动作许可和依赖顺序，执行器在派发前重查文件与记录版本。文件/下载审查器核对当前任务、引用、重名冲突和下载错误类型。自动恢复仅处理暂时性失败，取消的任务不恢复；同一任务每天最多两次恢复尝试。内容补全与自动整理合计每天最多 40 项，每轮每类最多 5 项。

归档支持单主文件及同名前缀字幕、封面，界面提供每个文件的原位置和目标位置。使用独占硬链接/取消旧链接完成移动，目标存在时拒绝覆盖，不支持该操作的文件系统保留原文件并报告失败。多主文件保留原有分 P 命名；其他记录、回收站及隐含共用字幕的引用阻止移动。

文件操作先将意图写入持久日志并同步，再移动文件，最后更新记录。进程中断后可接续，部分移动可撤销。已被外部修改的文件保留，等待人工处理；新生成的总结不阻止安全撤销。用户选择“保留现有归档”或撤销后，后台记住该选择，避免立即重复整理。

管理员可通过“查找未登记文件”复用现有找回流程，候选进入找回列表，不自动删除或推断私人文件归属。

## 前后端运行问题

每半小时核对页面资源和本机主页/任务接口；内存充足时每六小时以真实 Chromium 检查公开主页。暂时性巡检错误连续出现才进入既有事故与自修复队列。登录浏览器的代码异常立即上报脚本位置和错误类型，去重且每账号每天最多三条；不上传错误正文、堆栈、页面查询或媒体标题。

自修复沿用 Mac 工人的隔离工作区，增加独立的只读审查调用：

1. 提案工人读取代码和故障证据，提交补丁及复现测试。
2. 新审查上下文检查原因、完整候选改动、权限、数据保留和测试有效性；证据不足直接否决。
3. 宿主验证可修改路径，原有测试不允许修改；新增回归必须在基线失败、候选通过。
4. 部署前运行完整检查，树莓派测试使用生产数据库副本；上线后核对版本、文件哈希、页面、任务接口与新工人心跳。
5. 独立审查和上线回执均有效，才标记事故已修复并重试受影响任务。发布失败执行原有回滚。

账号可暂停新的媒体处理。系统故障处理沿用 `HEAL`、每日额度与尝试次数限制；没有 Mac/Codex 工人时保留队列，不宣称已修复。
